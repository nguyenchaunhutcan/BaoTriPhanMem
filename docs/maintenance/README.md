# Hồ sơ bảo trì

Mỗi yêu cầu có mã duy nhất theo dạng `CR-001`. Nhóm lập hồ sơ sau khi khảo sát ứng dụng, không điền lỗi hoặc kết quả giả để đủ số lượng.

## Số lượng theo đề bài

| Loại bảo trì | Số yêu cầu đề xuất tối thiểu |
|---|---:|
| Hiệu chỉnh lỗi | 3 |
| Thích ứng | 3 |
| Hoàn thiện | 3 |
| Dự phòng | 2 |

## Nội dung hồ sơ

Mỗi yêu cầu cần có phiếu đề xuất, tiếp nhận, phân tích tác động và phê duyệt theo mẫu giảng viên. Phân tích nêu các mục tài liệu, module và tập tin bị ảnh hưởng; so sánh ít nhất hai giải pháp về cách làm, nhân lực, công cụ, thời gian và chi phí dự kiến.

Đặc tả và thiết kế phải phân biệt phần gốc với phần thêm, xóa, sửa. Test case ghi dữ liệu vào, đầu ra mong đợi, đầu ra thực tế và kết quả. Kết quả thực tế chỉ được điền sau khi chạy kiểm thử.

Có thể dùng issue template của repo để theo dõi yêu cầu. Biểu mẫu GitHub hỗ trợ quản lý công việc, không thay thế các tài liệu cần nộp.

## Bảng truy vết

Khi có yêu cầu thực tế, thêm dòng vào bảng và dùng cùng mã xuyên suốt:

| Mã CR | Loại bảo trì | Đặc tả | Thiết kế | File/commit | Test case | Minh chứng | Trạng thái |
|---|---|---|---|---|---|---|---|

Chưa có yêu cầu bảo trì được chốt tại thời điểm thiết lập repository.
